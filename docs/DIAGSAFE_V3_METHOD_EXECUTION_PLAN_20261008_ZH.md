# DiagSafe-VL v3 方法

本文整理于 2026-10-12，描述当前实现中的研究问题、数据使用和学习机制。方法版本为 v3，数据契约为 v1。本文与 [数据说明](DATA_OVERVIEW_ZH.md)、[训练设置](DIAGSAFE_METHOD_EXPERIMENT_SETTINGS_20260929_ZH.md) 共同作为成员阅读入口。

## 1. 研究问题

用户向多模态助手上传图片、截图或文档时，安全判断需要结合画面信息、具体请求、使用目的和适用规则。同一张敏感图片可以用于新闻分析或防护说明，也可以被用于伤害他人。请求中看似普通的对象指代和用途描述，也可能在与图片结合后形成风险。

我们的项目研究这类交互中的可诊断安全审核。系统在回答前判断请求应怎样处理，在回答后检查候选内容能否发布，并给出画面、文字、意图和规则中的判断依据。研究覆盖暴力、自伤、仇恨、网络滥用、欺诈、隐私、医疗等危害类别，也关注教育、防护、授权操作和其他正常请求的有效帮助。

我们希望判断能够随实际输入变化产生合理响应。视觉证据被移除、图文指代被改变、使用目的发生变化或规则边界被调整时，模型需要正确识别变化影响了什么，以及哪些判断仍然成立。

方法学习对象是当前可见输入在当前规则下的安全判断。S1-S5 描述需要检验的能力，模型用同一份预训练语义输出路径回答这些问题。

## 2. 系统位置

审核器接在独立回答模型的前后。请求输入先进入审核器，allow 或 warn 可以进入回答环节；review 进入澄清或人工处理，refuse 拒绝当前请求的帮助。回答模型产生真实候选后，审核器检查发布动作。只有 response allow 可以原样发布。

请求 warn 表示允许有界帮助并提醒。回答 warn 表示候选还需要修改或补充提醒，两种动作在系统中分别执行。

请求的短路径只读取四类动作概率。需要完整诊断时，审核器对相同原始输入独立读取阶段、意图、规则和证据，最后组装输出。诊断预测保持独立，不将某项预测答案回填给其他问题。

## 3. 数据怎样进入模型

记可见输入为

\[
X=(Q,I_{1:m},O,P,C).
\]

Q 是自然用户 query，I 是按顺序排列的真实图片，O 是 OCR-only 输入中的转写，P 是本条实际给出的 policy deck，C 是待审核的候选回答。字段全部来自 `model_input`。

普通带图记录的 O 为 `null`，人工 OCR 与 caption 保留为核验参考。来源、样本 ID、组号、构组目标、gold 和复核历史均留在提示之外。OCR-only 保留自然 query 和实际转写。

| 数据任务 | 当前监督 |
| --- | --- |
| 请求与感知任务 | 请求动作、S1-S4 R/E/F、意图、policy ID/action、安全回答行为、已有证据位置 |
| 回答审核 | 发布动作、S5 E/F、安全回答行为、已有可见文本证据；候选存在决定 R5=1 |
| 原生辅助 | 来源实际提供的 prompt harm、response harm 或 image harm 等标签 |

没有候选回答时，契约记录 S5 为 `R=0, E=absent, F=not_applicable`。回答审核记录只提供 S5，S1-S4 和请求级意图、policy 标签为 `null`。

R 判断正确审核是否需要该能力，E 判断当前可见证据状态，F 判断该阶段定义的风险条件。三个字段各有自己的监督。图片含风险证据与用户能够获得安全帮助可以同时成立，风险标签和最终动作需要分别学习。完整定义见 [数据契约](../data_contract/v1/README_ZH.md)。

## 4. 一个共享语义模型

完整加载 `Qwen/Qwen3-VL-4B-Instruct`，保留官方视觉处理、语言主干、tokenizer 和原 `lm_head`。训练只更新语言 attention 的 q/k/v/o LoRA，视觉塔、merger、embedding、原输出层和其他基础参数冻结。

LoRA 使用 PEFT 默认初始化，初始增量 BA 为零。在相同提示和数值设置下，模型从原 Qwen 的函数起点开始学习。原输出层虽然冻结，经过它的语义损失仍向 LoRA 传播梯度。

所有判断共享

\[
p_{\theta,t}(y\mid X).
\]

t 表示一个固定的审核问题，例如当前请求动作、S2 风险、意图类别或适用规则。问题包含明确的字段定义。分类问题的目录由任务与可见输入决定，构组目标只在关系训练中使用。

每个问题直接读取 X 和自己的定义。动作、阶段和规则的 gold 分别用作各自目标，输入保持原样。证据问题独立生成短定位记录。

## 5. 分类与定位输出

### 5.1 分类

动作使用 `Decision:` 提示以及四个已有的单 token 延续 ` allow / warn / review / refuse`。读取原 LM head 在答案位置的 logits，在这四个候选中做 softmax。

其他离散字段使用写有完整定义的单 token 选项字母。当前实现逐项确认单 token 条件，在合法选项内归一化。policy ID 的候选来自实际 deck，并添加 `no_match` 和 `insufficient_policy`。policy action 独立判断，两项预测的一致性保留为可检验属性。

该概率定义适用于当前合法答案集合。训练 NLL 与推理使用相同候选及相同归一化。

空 deck 的请求遵循契约，返回 `insufficient_policy / insufficient_policy / review`。删除一条规则的输入仍按剩余 deck 判断。

### 5.2 证据

定位问题按阶段和可见字段提问，生成一个短 JSON。文本记录包含实际字段、规则 ID、字符区间和所选原文；图像记录包含图片序号和矩形区域。

文本偏移量按 Unicode 字符计数，区间左闭右开。policy span 相对于所选卡片的 `rule_text`。图像 gold 使用原图归一化 `[x,y,width,height]`，模型答案使用 Qwen 的 0-1000 `[x1,y1,x2,y2]` 坐标，训练与推理按同一约定换算。

当前定位训练只使用 E=present 且已有可靠位置的正标注。缺少定位的字段保持无定位监督，旧记录中 E=absent 或 uncertain 的标记保留供核对。完整推理根据可见字段选择问题目录，输出中的非法偏移、解析失败或截断按实际情况记录。

证据生成在单个答案内使用自回归解码，其答案保持在这个定位问题内。

## 6. 统一学习目标

绝对监督学习每个成员的正确答案，关系监督学习同一判断函数对已核实输入变化的响应。两者使用相同模型参数和相同合法集合概率。

\[
\mathcal L(\theta)
=\mathcal L_{\mathrm{semantic}}(\theta)
+\lambda\mathcal L_{\mathrm{contrast}}(\theta).
\]

### 6.1 绝对监督

每个已知分类字段使用合法候选集合内的 NLL。已有正定位使用短答案的平均 token NLL。

请求、回答和原生辅助三个任务分别按根或请求上下文计算平均损失，三个任务的期望权重各为 1/3。在一个根内，先平均成员，再平均该成员的分类和定位问题。定位答案内部先平均 token，长证据不会仅因 token 数多而获得更高权重。

请求根由原图、确认的图片家族及来源关系归并。回答按完全相同的可见请求上下文归并，同请求多条候选在上下文内平均。原生辅助保留自己的根和真实监督范围。

### 6.2 关系监督

对组 g 的字段 t，P 堆叠成员的预测概率，Y 堆叠对应 one-hot 标签，D 保存已核实的输入差分行。当前实现对 D 的行空间作常量 SVD，得到正交基 B，损失为

\[
\ell_{g,t}
=\frac{\left\|B_{g,t}\left(P_{\theta,t}(g)-Y_{g,t}\right)\right\|_F^2}
{\operatorname{rank}(D_{g,t})\,K_t},
\]

其中 K 是该字段的合法类别数。正交化使重复或线性依赖的关系行保持相同权重。SVD 只处理标注侧的常量矩阵。

关系项按根或请求上下文簇平均，再在簇内平均关系组，在组内平均有效字段任务。关系所需的额外前向只计算关系损失，成员的绝对监督权重保持原有总量。

只使用 `single_factor_verified` 的有效关系和有明确标签的字段。自然匹配、混杂或尚未确定的关系保留成员监督。当前非目标稳定记录只支持逐项核实的 F 稳定，R/E 使用自身绝对标签。

绝对监督锚定各成员答案，差分监督约束已观察的变化方向。未覆盖关系的泛化仍依赖数据、模型能力和优化，需要另行检验。

## 7. 五个阶段的关系怎样使用

| 阶段 | 输入变化 | 关系训练依据 |
| --- | --- | --- |
| S1 | 视觉或 OCR 证据改变 | 两端实际可见信息及独立 F1、动作标签 |
| S2 | 真实图片与自然 query 的交叉组合 | 完整四角与各角独立 F2、动作标签 |
| S3 | 请求用途或意图改变 | 保留其他因素后的实际语义差异 |
| S4 | 规则边界改变，或规则顺序、ID 改变 | 边界关系与语义不变性分别核实 |
| S5 | 相同可见请求下候选回答执行改变 | 真实回答内容及独立安全判断 |

S2 四角固定为

\[
x_{00}=(I_0,Q_0),\quad x_{01}=(I_0,Q_1),\quad
x_{10}=(I_1,Q_0),\quad x_{11}=(I_1,Q_1).
\]

四角共享 deck 和 split，图片与 query 因素之外的输入保持约定一致。四角均有确定 F2 时，交互使用

\[
\Delta p=p_{11}-p_{10}-p_{01}+p_{00},\qquad
\Delta y=y_{11}-y_{10}-y_{01}+y_{00}.
\]

非零交互和零交互对照分开统计，确定的零交互也可以监督其真实差分。含不确定角的组保留 uncertain 绝对监督，其他经过核实的两端关系可以继续使用。

索引中的 `Delta_gold` 按各角二值 F2 计算。关系目标中的 p 和 y 分别为完整类别概率向量与 one-hot 标签向量，与其他字段的差分计算采用相同表示。

S4 的 ID 或顺序关系先根据核实的规则语义映射对齐候选。真实规则边界变化单独建设和统计。

S5 使用同一个实际请求中的真实候选回答，逐条区分安全性、有用性、过度拒绝和危险执行。chosen/rejected 提供来源偏好信息，执行差异需要额外核对。

## 8. 训练流程

从同一公开 Qwen 基础模型重新初始化，使用一个共享 LoRA、一个 AdamW 优化器和一个覆盖完整三轮的 cosine 学习率计划。请求、S5、原生辅助和有效关系从第一轮共同参与。

固定清单每轮遍历 40013 个根或回答上下文单位，四卡每轮 626 次更新，三轮共 1878 次。一个完整根及一个关系任务保持在同一设备，更新内使用小视图批次依次反传，最后一次反传进行 DDP 同步。

每轮包含 153603 个分类视图、23424 个正定位字段视图和 13797 个关系前向视图。视图是同一批根的不同审核问题，独立数据量仍按根、成员、回答和有效组分别计算。

`v3` 使用 lambda=1。`no_relation` 使用完全相同的问题、成员、关系前向和训练顺序，将 lambda 设为 0，用于隔离关系损失的贡献。完整三轮使用固定 seed 清单，逐轮保存 checkpoint。

正式选择量为自然 dev 请求动作平均 NLL 与回答发布动作平均 NLL 的等权平均，只比较完整 epoch 的 checkpoint。公开集合和隐藏测试保持评测用途。

详细参数见 [训练设置](DIAGSAFE_METHOD_EXPERIMENT_SETTINGS_20260929_ZH.md)。

## 9. 数据要求与贡献边界

方法需要自然图文情境、可靠的完整阶段标签、当前可见证据、真实规则判断以及有效输入关系。图文绑定、意图变化和规则边界需要足够多样的根情境；重复曝光用于优化，覆盖由实际新情境决定。

新增数据优先补视觉必要情境、hard benign、warn/review、薄弱危害类别和图文回答执行差异。授权自然照片可以仅裁切原像素，原图与裁切坐标保留，同源成员放在同一 split。

本项目希望建立从诊断标签到实际处理动作的可检验联系，并用已核实输入变化约束同一语义判断函数。因果解释范围是输入干预下的诊断响应。神经元级中介、证据唯一性和域外安全保证需要额外研究证据。
