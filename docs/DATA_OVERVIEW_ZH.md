# DiagSafe-VL 当前数据

本文按 2026-10-16 的 v6 正式方法记录与读取实现整理，当前发布为 `releases/visual_refusal_fill_20261015`。下列数量对应冻结 train 清单，不是实时标注进度，也不表示所有记录已完成人工终审。数据、媒体和内部复核记录不随代码仓库上传。

阅读字段定义时使用 [数据契约 v1](../data_contract/v1/README_ZH.md)，阅读训练中的监督方式时使用 [v6 方法](DIAGSAFE_V6_GUIDE_ZH.md#method)。[返回首页](../README.md)。

## 1. 数据解决什么问题

我们需要知道模型是否理解当前可见图文、怎样应用实际规则，以及候选回答是否会执行或扩大风险。数据同时保留完整审核标签和已核实输入变化，让每个具体判断及其变化都能得到监督。

自然请求覆盖常规帮助、敏感分析、风险请求和信息不足的边界情境。关系组围绕视觉证据、图文绑定、意图、规则和回答执行设计。原生辅助提供更广泛的安全监督，使用范围按来源真实标签确定。

## 2. 数量的口径

根情境表示归并后的原始请求背景。成员是该根下的一条具体输入，图片、请求或规则变化可能产生多个成员。回答候选按条计数，相同可见请求下的多条回答归到同一上下文。

有效组、关系边和 S2 四角分别计数。一个组可以包含多条边，同一根也可以承载多个组。展开审核问题属于训练视图，统计规模时仍保留其父成员和根。

## 3. 当前训练组成

| 数据 | 当前数量 |

| Core 归并请求根 | 3866 |
| Core 请求成员 | 7917 |

Core 包括请求判断和感知任务，提供 S1-S4 R/E/F、意图、policy ID/action、请求动作、安全回答行为和已有证据。S5 回答审核只提供回答任务支持的标签。原生辅助使用来源的 prompt、response 或 image 安全监督。

| 已登记的带图覆盖 | Core 请求 | S5 回答 |
| --- | --- | --- |
| 带图成员 / 候选 | 5883 | 2452 |
| 全部成员 / 候选 | 7917 | 3907 |

带图成员包含同图变体、多图和真实像素裁切，不等于独立视觉根，也不表示图片对判断一定必要。同一根可以同时包含带图成员和移除图像后的成员。当前版本不沿用 v3 的模态根数、动作成员分布或来源槽位比例充当 v6 统计。

训练先按根和回答上下文加权，再按同根成员平均。v6 从实际训练系数计算动作与确定风险类别的预算，不能由成员比例直接推断有效训练权重。实际运行将这些系数保存在 `risk_action_balance.json`。

## 4. 来源和请求构造

现有来源登记包括 WildGuardMix、Aegis 2.0、SPA-VL、VLGuard，以及项目逐条编写的自然请求。图片来源包括 LLaVAGuard-SMID、VLGuard、GuardReasoner-VLTrain-Image、SPA-VL 和 Wikimedia Commons；新增素材的具体来源以每条记录的 `source` 和 `images` 为准。

图片来源与请求来源可以不同。使用来源数据集中的图片，不代表 query 也是来源原文。来源原请求、项目编写请求和替代请求保留各自的 `query_provenance`，不从数据集名称推断样本模态、安全标签或授权状态。

普通带图输入只提供图片像素和自然 query，人工 OCR、caption 和构组目标留在模型提示之外。OCR-only 保留自然 query 和真实转写。裁切图片只保留原始像素，内部保存原图与裁切坐标。

## 5. S5 候选回答

当前 3907 条候选归入 2042 个完全相同可见请求上下文，其中 2452 条带图。候选可以来自来源数据集或真实模型调用，保留来源记录、原始文本及实际生成设置。它们不是回答动作标签的文字展开，也不能按候选数直接统计独立请求情境。

回答标签根据内容和当前输入判断。来源 chosen/rejected 保存偏好信息，候选的安全性、有用性及原样发布条件分别核对。安全但过度拒绝的回答可以满足安全发布条件，有用性单独记录。

## 6. 因果关系与 S2 四角

当前读取范围含 2784 条已纳入训练的关系边，形成 1434 个关系实验对象，归入 1012 个请求根或回答上下文簇。关系对象可包含多条边；同一根也可参与多个对象。这个范围包含控制与不变性任务，不能把边数或对象数直接称为独立有效因果组数，也不沿用旧版本的分阶段 626 组充当当前统计。

| S2 四角类别 | 组数 |
| --- | --- |
| 确定的非零交互 | 222 |
| 确定的零交互对照 | 67 |
| 含不确定角 | 28 |
| 合计 | 317 |

四角索引明确引用真实图片与自然 query 的四个组合，各角独立标签和实际输入共同决定关系。不确定四角不冒充完整确定交互，其内部已核实局部关系可以单独使用。R/E 的监督继续来自各成员标签，不从构组目标推导。

S4 将真实规则边界变化与规则顺序、ID 不变性分开。S5 的执行关系要求相同可见请求以及实际成立的回答执行差异。v6 对已核实非恒定字段使用固定标签计数下的条件匹配；同标签常量分量损失为零，成员绝对监督继续保留。非目标稳定性单独评测，不新增一致性惩罚。

## 7. 开发集与划分

自然 dev 包含 299 条请求和 200 条回答审核。完整 dev 另读取机制成员，规模以实际导出和评测分母为准；自然分布与机制集合不混计。

| 自然 dev 动作 | 请求 /299 | 回答审核 /200 |
| --- | --- | --- |
| allow | 175 | 158 |
| warn | 22 | 14 |
| review | 17 | 3 |
| refuse | 85 | 25 |

回答 review 只有 3 条，相关召回与均衡选择量对个别样本敏感。v6 在完整 epoch 的自然 dev 上选 checkpoint，不使用隐藏测试或公开 benchmark 调整方法、阈值和训练规模。

train、dev、test_hidden 按根图、来源记录、确认的近重复和 query 模板家族隔离，再在各集合内部形成变体。原图与裁切放在同一 split。外部 benchmark 保持评测用途，隐藏测试保持封存。

全量人工终审尚未认证。父发布曾记录部分图片缺少近重复向量，该历史缺口不能据本次文档更新视为已解决，也不能据目录划分宣称零污染。

冻结范围中已知 70 个证据字段存在 E=absent 与正定位冲突，另有 1 个字段尚未建立定位。训练投影保留原记录和独立分类标签，只屏蔽对应歧义定位块。`null` 表示未建立该定位监督，不能改读为 E=absent 或 F=0。投影实现见 [v5_data.py](../causal_diagsafe/training/v5_data.py)。

以 `releases/visual_refusal_fill_20261015` 为发布根目录，训练与 dev 读取以下文件。

图片 URI 指向数据服务器上的实际媒体。迁移到其他机器时，需要同时提供媒体并更新路径，保持图片顺序和原图尺寸。数据、媒体、完整样本输出、模型权重与内部复核文件由实验目录单独管理，Git 提供读取代码、schema 和方法说明。

## 9. 后续覆盖判断

本轮固定版本用于完整训练，不凭总条数宣布数据充分。是否继续扩量应由固定 dev 上的学习曲线、视觉必要情境、不同危害边界和结论所需精度决定；比较因果组规模时保持 Core、辅助数据、主干和比较协议一致。

新增工作优先补真实视觉必要情境、不同图文关系、hard benign、warn/review、薄弱危害类别、真实规则边界和图文回答执行差异。普通文本扩量和同图重复不会增加这些情境的覆盖。

纠错继续依据可见输入与字段定义进行，关系有效性与成员标签分别核对。关系不成立但成员标签可靠的记录可以继续用于绝对监督。
